# Cluster 2 worker integration

The teammate implements `lib/economy/*`, its unit tests and fixtures. The lead owns these Convex transitions; no engine replacement or hardcoded bidder/service implementation is included here. This note is the integration boundary, not evidence that the worker is already running.

1. `api.jobs.start` authenticates the owner, validates selected columns/options and mission deadline, persists the root job, freezes the brief, and emits `AUCTION_OPENED`. Idempotent retries reuse the root job; changed options are rejected.
2. Once the engine package is available, connect a bounded internal scheduler/driver to compute individual bids and ranking using its real exports. Persist offers with `internal.workflow.recordBid`; negotiate using `negotiate` (rounds 2–3); award using `award` with the actual ranking explanation. Every write rechecks current state and financial/capacity bounds. Do not submit fixture worker data as demo evidence.
3. For an eligible summary job, `subcontract` opens one normalization child within the parent award. It initially reduces parent holdback by the allocated child budget. Awarding the child sets parent holdback to parent award minus actual child price, preserving the original obligation exactly. The parent reservation includes the child; do not add them again at settlement.
4. Call `internal.workflow.executionContext` before running a service. It returns the real source CSV for a direct job, or the approved child's stored CSV and `dependencyDeliverableId` for a parent with a child. Incomplete child work blocks this read. Use this returned input in the real service and independent verifier; do not bypass it with the original dataset.
5. Store the actual service result using `submit`, including the exact `dependencyDeliverableId` for a parent. Input/output hashes and evidence snapshots should be added with the actual engine/verification binding during integration; a stored reference alone is not proof of correct computation.
6. Call the independent verifier on the stored deliverable and the bound execution input, then persist its actual verdict/checks via `recordVerification`. A fail permits one revision, then opens a dispute; `needs_human` opens a dispute directly. Pass checks must all pass. No browser may invoke these internal functions.
7. `api.jobs.resolveDispute` is owner-only. It records the decision and reason. Failed child work opens a parent dispute; even the owner cannot approve a parent whose child is not approved. Parent rejection remains possible. Finalization adds one deterministic reputation event per job (+10 accepted, -5 rejected) and marks the contract completed/failed. Payment authorization is a separate future state machine.

Current testing covers state/budget/privacy invariants using explicit internal fixtures, plus live opening/canceling of an auction. It does not certify independent bidding formulas, CSV transformations, verifier correctness, or an integrated scheduled economy until the teammate package is present. No public worker endpoint or arbitrary transfer endpoint is introduced.

## Pricing privacy and explicit negotiation actors

Use the internal `workflow.pricingContext(jobId)` for worker pricing data. Buyer-facing job, economy and profile queries return allowlisted projections and omit seller minima, reserves and free-text cost diagnostics. Existing raw worker diagnostics are retained internally; legacy event detail for bid/negotiation/award events is also redacted at the read boundary. Public explanations are currently conservative eligibility/action summaries; reviewed structured ranking-score explanations remain part of engine integration. Do not put private numbers into public service deliverables or new unreviewed event types.

`lib/agent-directory.ts` is browser-safe metadata. The existing `AgentProfile`/`INITIAL_AGENTS` exports in `lib/agents.ts` remain compatible with the teammate's pure engine and tests, but their deterministic fixture floors are published source and must not be described as secrets. Real backend floors can be configured through server-only `AGENT_PRIVATE_FLOORS_JSON` (existing seller IDs to canonical positive integer yoctoNEAR strings, max 10 entries). Malformed configuration fails closed. Pass the private profile from the internal context to the engine instead of importing fixture prices as production policy. The trusted marketplace operator can read this backend configuration; this is data-access separation, not cryptographic secrecy from the operator or concealment of inferences from public offers.

Configure that optional variable on the Convex backend using its dashboard or the interactive `npx convex env set AGENT_PRIVATE_FLOORS_JSON` command. Local environment worksheets are not automatically synchronized. Deploy frontend and backend changes together: old clients expecting pricing fields must reload, and old internal worker callers must supply the required role. No confidential limits are retained in public responses for backward compatibility.

New `workflow.negotiate` calls require `actorRole`. The existing bounded message sequence is explicit: seller's initial bid is round 1, buyer response is round 2, seller reply is round 3. A root buyer's actor ID is derived from the job owner; for a subcontract it is derived from the parent awarded seller. Seller identity comes from the bid. Callers cannot supply actor IDs. Buyer proposals are checked against the buyer cap without testing a hidden seller floor; seller counters/acceptances must satisfy the seller's stored minimum and current configured reserve. Acceptance/rejection must reference the exact preceding offered price. An unaccepted final counteroffer never becomes an award.

Actor fields are optional in storage solely to preserve legacy rows. Old rows lacking either actor identity/role are labeled unknown and cannot be continued or used for new awards. Do not guess or silently backfill roles; cancel an unawarded legacy auction and create a new mission, or perform a separately reviewed provenance-preserving migration. Existing awarded contracts, approvals, receipts and reservations are not rewritten. Recheck current private floors before award; a changed floor requires reassessment.

CSV parsing now uses an explicit comma delimiter consistently for mission validation and selected-column parsing, including a valid one-column CSV. This avoids delimiter-guessing failures without altering the exported service/action types. The teammate's `lib/economy/*` files remain untouched.
