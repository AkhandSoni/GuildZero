## Outcome and boundary

Expose the existing marketplace to an external assistant through a local TypeScript stdio process. Keep Next.js as the human authentication/approval interface and Convex as the only application backend, database and scheduler. MCP adds tool interoperability; it does not add an LLM, wallet, payment mandate or an economic engine.

Flow: external MCP client → local stdio adapter → fixed authenticated Convex HTTP action → transactional credential/scope/ownership validation → existing operations and public projections. Human approval remains a separate authenticated UI action. Prepare/request-approval never authorizes, schedules a signer or sends funds.

No NEAR account, funded wallet, paid API or preexisting `.env.local` is needed for offline tests. Actual local Convex requires an isolated deployment generated by its CLI and the supported project Node 24 runtime. Payment-disabled local workflows show locked output and truthful readiness states. Existing env files and owner credentials are never copied. No live payout, public deployment or merge is part of this work.

## Design freeze

- Official stable split MCP SDK v2 server/client packages, pin exact compatible releases after registry/source verification (currently 2.4.0); use Zod 4 strict schemas shared by adapter and gateway.
- Local stdio only. stdout is JSON-RPC only, diagnostics are sanitized stderr. No HTTP MCP listener, public tunnel, legacy SSE, hosted inference or sampling.
- Exactly the 13 names in the issue, prefixed `guildzero_`. Fixed tool/argument union, strict per-tool input/output schemas, finite input/output/element/deadline bounds. Tool annotations are descriptive and never permissions.
- Versioned application success/error envelopes, actual native state alongside any normalized workflow status. Ordinary locked/pending results remain truthful domain outcomes; auth/validation/network errors use stable sanitized codes. Never expose raw exceptions.
- Immutable credential per child process from an absolute private token file (environment token only where necessary). Fixed configured Convex site origin, HTTPS remotely, loopback HTTP locally, no redirects, model-selected URLs or arbitrary function forwarding.
- Human-session-only named integration issuance/list/revoke/revoke-all. At least 256 random bits, digest-only storage, one-time secret response, default one-hour/max 24-hour TTL, explicit scope and optional owned-mission restriction. Define logout semantics in the UI/runbook; independently issued credentials persist until expiry/revoke, so users must revoke separately before leaving a shared host.
- Every backend operation loads the active credential and owner, verifies scope/mission constraints, applies bounded rates and accesses/writes data in one transaction. No general Convex sessions, forged identities or credential issuance via MCP.
- Existing mission/service validation and auction/payment preparation logic become minimal explicit-owner trusted helpers shared with current authenticated wrappers. Current public auth checks remain intact.
- Mission creation stores integration/owner/request ID plus canonical input fingerprint transactionally. Same ID/same input returns original; changed input rejects. Existing root-job/payment-intent identities remain authoritative. No automatic retry under a fresh ID.
- All private projections are allowlisted. Full result content comes only through `deliveryAccess`; verification/events cannot leak locked values, private reserves, cost policy, worker snapshots or claim tokens. Catalog history is owner-scoped and bounded.

## Tool and scope matrix

| Tool suffix | Required scope | Operation and limits |
| --- | --- | --- |
| list_services | catalog:read | Five supported services, exact limits/options/output formats |
| list_agents | catalog:read | Public identities/capacity plus honestly labeled bounded owner history |
| create_mission | missions:create | Strict brief, request ID, inline CSV; no spending permission |
| get_mission | missions:read | Owned brief/status, bounded job references; no raw CSV default |
| list_missions | missions:read | Owner-only pagination, 1–50 rows, bounded filters |
| start_auction | auctions:start | Saved options, existing root idempotency; never acknowledge unfunded preview for human |
| get_auction | missions:read | Public bids/negotiation/contracts/scores and actual state |
| get_activity | activity:read | 1–100 safe ordered events, truncation |
| get_verification | verification:read | Bounded code/pass/verdict metadata; no hidden computed values |
| get_result | results:read | Policy-released latest output, otherwise allowed locked preview/reason/obligations |
| get_payment_status | payments:read | Exact safe intent/attempt/state and validated receipt metadata |
| prepare_payment | payments:prepare | Existing eligible exact intent; no caller recipient/amount or signing |
| request_payment_authorization | payments:request-approval | Existing intent binding and fixed-origin UI link; never authorize |

Inputs retain 64 KiB/500 rows/32 columns per CSV and existing service-specific numeric/header/group constraints, with a separate JSON-envelope bound for escaped/two-input CSV. Monetary strings stay canonical integer yoctoNEAR. Deliverables remain <=128 KiB. CSV/notes/results are untrusted data; no URL fetch, filesystem path, shell or dynamic schema from a tool argument.
